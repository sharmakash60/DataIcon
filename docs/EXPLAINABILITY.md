# Model Explainability & Diagnostic Analysis Engine

## 1. Overview & Provenance Guarantee

DataPilot provides an enterprise-grade, mathematically grounded **Model Explainability Engine**. Unlike black-box automated systems or generative AI wrappers that hallucinate rationalizations, DataPilot enforces a **Zero-Hallucination Architecture**:

1. **Model-Derived Facts (`source='model_derived'`)**: All quantitative facts—including global SHAP attributions, beeswarm summary coordinates, dependence interactions, partial dependence curves, sample-level waterfall attributions, permutation drops, and error slices—are computed directly from local model artifacts and validation distributions on the client data plane.
2. **Advisory AI Narratives (`source='ai_generated'`)**: Qualitative interpretations generated by Large Language Models are strictly sequestered from the numeric data plane. The LLM cannot mutate, fabricate, or overwrite numeric model artifacts. Any AI-generated text is explicitly badged and carries mandatory disclaimers.
3. **Domain Assumptions (`source='user_assumption'`)**: Domain constraints and expert heuristics provided by business stakeholders are recorded as auditable assumptions.
4. **Privacy Containment**: Raw training datasets are never transferred to the control plane. Only bounded, aggregated statistical artifacts, quantiles, and capped local sample attributions (maximum 20 representative instances) pass the export gate.

### 2.1. Global Feature Importance, Direction & Distribution

Global feature importance quantifies the overall contribution of each feature to the model's predictions across the evaluation dataset.

For each feature, the system displays:
- **Feature Name**: Authoritative schema column identifier.
- **Importance Magnitude**: Mean absolute Shapley value ($\frac{1}{N} \sum_{i=1}^N |\phi_j^{(i)}|$) or tree gain metric.
- **Direction where Supported**:
  - `▲ Increases (+)`: Positive correlation with model predictions (increasing the feature pushes predictions higher).
  - `▼ Decreases (−)`: Negative correlation with model predictions (increasing the feature pushes predictions lower).
  - `~ Non-linear`: Non-monotonic relationship where impact varies across the feature domain.
- **Distribution Quantiles**: Empirical validation distribution summary:
  - $\text{Min}, P_{25}, \text{Median}, P_{75}, \text{Max}, \text{Mean}, \text{Std}$.

---

### 2.2. SHAP Summary Plot (Beeswarm Representation)

The beeswarm summary visualization illustrates both the magnitude and the direction of feature effects:
- Each row represents a feature, sorted by global importance.
- Each point corresponds to an evaluation sample.
- **X-axis position**: The SHAP value ($\phi_j^{(i)}$)—whether the feature pushed that instance's prediction higher ($> 0$) or lower ($< 0$).
- **Color gradient**: The normalized feature value of that instance ($0.0 = \text{low / blue}$ to $1.0 = \text{high / red}$).
- **Interpretation**: If high values (red) cluster to the right ($+X$), high feature values increase prediction probability (e.g. high `transaction_amount` increases fraud probability).

---

### 2.3. SHAP Dependence Analysis

SHAP dependence plots demonstrate how a single feature's value directly governs its SHAP attribution across the dataset:
$$\text{Plot: } x_j^{(i)} \quad \text{vs} \quad \phi_j^{(i)}$$
- Uncovers non-linear thresholds, inflection points, and saturation boundaries (e.g., tenure diminishing returns beyond 24 months).
- Reveals feature interactions through secondary feature coloring ($z_k^{(i)}$).

---

### 2.4. Local Prediction Explanations

Sample-level waterfall explanations allow practitioners to audit specific high-stakes predictions:
- **Prediction**: The continuous model output or discrete class assignment.
- **Probability / Value**: The calibrated prediction probability (e.g. $88.0\%$ fraud risk) or regression target estimate.
- **Baseline Expectation**: The base value ($\mathbb{E}[f(X)]$) from which local explanations diverge.
- **Top Factors Increasing Prediction**:
  - Sorted positive contributions: $\phi_j > 0$.
  - Indicates the precise feature value for that sample and the positive push ($+\Delta$).
- **Top Factors Decreasing Prediction**:
  - Sorted negative contributions: $\phi_j < 0$.
  - Indicates the precise feature value for that sample and the downward mitigation ($-\Delta$).
- **Waterfall Chart**: Bilateral divergence diagram displaying cumulative attribution from base value to final prediction.

---

### 2.5. Permutation Feature Importance

Permutation importance measures empirical dependence on a feature by evaluating validation metric degradation after randomly shuffling that column:
$$I(f_j) = \mathcal{M}(X_{\text{permuted}, j}, y) - \mathcal{M}(X_{\text{orig}}, y)$$
- Evaluates $N$ repeats with standard error ($\pm \text{SE}$).
- Independent of model architecture (works across tree ensembles, linear models, neural architectures).
- Guards against collinear feature inflation common in default tree impurity metrics.

---

### 2.6. Partial Dependence Plots (PDP) & ICE Lines

Partial dependence curves reveal the marginal effect of one or two features on the model's predicted outcome:
$$\hat{f}_{x_S}(x_S) = \frac{1}{n} \sum_{i=1}^n \hat{f}(x_S, x_{C}^{(i)})$$
- Evaluates model predictions over an empirical grid spanning feature range $[\text{min}, \text{max}]$.
- Averages out the effects of all complementary features ($x_C$).
- Displays individual conditional expectation (ICE) curves where available to detect subgroup heterogeneity.

---

### 2.7. Error & Subgroup Performance Analysis

Identifies systemic failure modes and performance disparities across data slices:
- **Classification**: Full confusion matrix with True Positives, True Negatives, False Positives, False Negatives, and class-conditional error rates.
- **Regression**: Error distribution metrics including Root Mean Squared Error (RMSE), Mean Absolute Error (MAE), Mean Residual, and Max Error.
- **High-Error Slices (Underperforming Segments)**: Automatically isolates segments where model error exceeds baseline by $\Delta > 10\%$.
- **Optimal Slices**: Isolates segments where model performance achieves peak precision/recall.

## 3. What-If Scenario / Sensitivity Analysis

### 3.1. Purpose & Interactive Simulation

The What-If Simulator enables practitioners and business analysts to probe model sensitivity by testing counterfactual feature modifications on specific customer profiles.

**Example Scenario**:
- **Baseline Profile**: Customer Sample #42 with $\text{Tenure} = 8 \text{ months}$, Predicted Churn Risk $= 70.0\%$.
- **User Modification**: Adjust $\text{Tenure} \to 24 \text{ months}$.
- **Simulated Prediction**: Predicted Churn Risk drops to $35.0\%$ ($\Delta = -35.0\%$).
- **Attribution Breakdown**: Shows the marginal contribution shift ($\Delta_j$) for each altered feature and recomputes top increasing/decreasing factors.

### 3.2. Mandatory Non-Causal Disclaimers

> [!CAUTION]
> **MODEL SENSITIVITY / SCENARIO ANALYSIS — NOT CAUSAL EVIDENCE**
> 
> What-If simulations project statistical model variations based on correlations captured from the historical training distribution.
> 
> - **Correlation $\neq$ Causation**: A model finding that customers with 24 months tenure churn less frequently does NOT prove that artificially keeping a customer for 24 months will cause them not to churn.
> - **Omitted Variable Bias**: Latent unobserved factors (e.g., customer satisfaction, product fit, pricing changes) may confound observed relationships.
> - **Intervention Fallacy**: What-If analysis answers *"What would the model predict for an entity that looked like this?"*, NOT *"What will happen if we take action to change this attribute in the real world?"*
> 
> All UI views and API responses return the mandatory sensitivity warning and require practitioner sign-off before operationalization.

## 4. API Endpoints & Schemas

### 4.1. Ingestion Endpoint
`POST /api/v1/organizations/{org_id}/projects/{project_id}/experiments/{exp_id}/explainability`
- **Permission**: `experiment:run`
- **Request Body**: `IngestExplainabilityRequest`
- **Response**: `ExplainabilityReportOut` (Status 201)

### 4.2. What-If Simulation Endpoint
`POST /api/v1/organizations/{org_id}/projects/{project_id}/experiments/{exp_id}/explainability/{report_id}/what-if`
- **Permission**: `experiment:view`
- **Request Body**:
```json
{
  "sample_index": 42,
  "baseline_features": {
    "tenure_months": 8,
    "monthly_charges": 75.0
  },
  "modified_features": {
    "tenure_months": 24.0
  }
}
```
- **Response**:
```json
{
  "baseline_prediction": 0.70,
  "scenario_prediction": 0.35,
  "delta": -0.35,
  "baseline_probability": 0.70,
  "scenario_probability": 0.35,
  "feature_shifts": [
    {
      "feature_name": "tenure_months",
      "original_value": 8.0,
      "new_value": 24.0,
      "estimated_impact": -0.35,
      "direction": "decreases_prediction"
    }
  ],
  "top_factors_increasing": [],
  "top_factors_decreasing": [
    {
      "feature_name": "tenure_months",
      "shap_value": -0.35,
      "feature_value": 24.0,
      "impact_magnitude": 0.35,
      "effect": "decreases_prediction",
      "source": "model_derived"
    }
  ],
  "disclaimer": "⚠️ MODEL SENSITIVITY / SCENARIO ANALYSIS — NOT CAUSAL EVIDENCE: This simulation projects model output variations based on statistical correlations in the trained model distribution. It does NOT establish causal inference or guarantee that an intervention in the real world will produce this outcome.",
  "method": "partial_dependence_interpolation",
  "source": "model_derived"
}
```

### 4.3. AI Narrative Generation
`POST /api/v1/organizations/{org_id}/projects/{project_id}/experiments/{exp_id}/explainability/{report_id}/narrative`
- **Permission**: `experiment:view`
- **Guarantees**: Populates qualitative summaries only (`source='ai_generated'`). Strict sanitization strips any fabricated numeric claims.
